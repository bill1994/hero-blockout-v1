## 二、被推翻的结论

### 1. ❌「橙件是实心长方体、没有腔体」——错

报告第 140 行先写「说明 z 1.074 以上是空的？不，反过来读」，然后读反了。

**射线证据**（`scratch/verify_audit.json`）：

```
down_at_x1_y0    : Machine_Chute@1.074 → Machine_Chute@1.039 → ESCAPE
down_at_x1_y038  : Machine_Chute@1.556 → Machine_Chute@1.074 → Machine_Chute@1.039 → ESCAPE
```

若橙件是 z 1.039…1.556 的实心块，y=0 处首命中必然是 **1.556**。实际首命中 **1.074** —— 中心上方是空的。

**切片证据**：`Machine_Chute` 在 z=1.15 / 1.30 / 1.45 三个高度**一个顶点都没有**，顶点只集中在 z≈1.05 和 z=1.556。这是「底板 + 竖直大侧壁」的放样结构。

**实际结构**：底板 z 1.039–1.074（厚 0.035）+ 两侧壁到 1.556，y ±0.415 外 / ±0.38 内。**是 U 形槽，槽是真实存在的。**

**真正的问题**是法线整体朝内（signed_volume 负 + boundary_edges=0 + 闭合），渲染时被当成实心块看。修复顺序应是：

1. 先 `Recalculate Outside` 翻法线 → 槽就显形了
2. 再判断壁厚/深度够不够，不够才谈重建
3. 最后才做挖穿机身 + 修唇橙关系

报告直接建议「重建 U 槽」（方案 A 重新放样 192 顶点），**把翻面问题当成了缺件问题**，工作量估计偏大。

### 2. ❌「参考爪是浅杏色 sRGB(0.90,0.81,0.69)，当前琥珀橙偏色」——方向反了

参考图逐像素采样（`scratch/sample_ref_colors.py`）：

| 采样 | RGB | sRGB |
|---|---|---|
| 球心 median | **(243, 166, 94)** | (0.953, 0.651, 0.369) |
| 最饱和橙像素 | (226,116,27) / (241,159,59) | (0.886,0.455,0.106) / (0.945,0.624,0.231) |
| 全图橙色像素数 | **2,125 个**，左视图 bbox x 144–639 y 486–765 | — |
| 报告的采样框 `P0_claw_and_ball` | (210,209,207) | 灰背景，框歪了 |

**参考爪就是饱和橙色**，不是浅杏奶油。报告给的 (0.903,0.812,0.694) = RGB(230,207,177)，是背景/机身的色。

所以「爪色偏橙、需改浅杏」这条建议**方向是错的**——当前 `MAT_Color_Amber` 的橙色与参考同属橙色系，不该往浅杏改。

### 3. ⚠️ 夹爪角度数字对不上

报告：f147 三爪 123.7° / 123.7° / 112.6°，最大偏差 7.4°。
实测（f147 `rotation_euler.z`）：L **+42.8°**、C **0°**、R **−42.8°** —— 报告写的 ±56.31° 与 C −180° 在文件里找不到对应值。

轴向正交渲染（`C:\scratch\claw_axis_f147.png`，沿手腕轴看）显示：**两根手指挤在球的前侧上下，第三根完全被球遮挡**，不是 120° 等分。

结论方向（不均分）成立，但**实际偏差比报告严重**，且数字来源存疑。

## 三、报告漏掉的

1. **法线翻转不是孤例**：`P1_ChuteRail` signed_volume **−0.0504**、`P2_OutletBand` **−0.002058** 也是负的。报告只点了 `Machine_Chute`。这是系统性的绕序问题，应统一处理而不是逐件重建。
2. **`P1_ChuteSeat` 是死件**：`hide_viewport=True` + `hide_render=True`，带 SUBSURF + NODES，bbox z **−0.618…−0.245**（在地面以下）。不参与渲染，报告未提。
3. **缺一条最硬的空心证据**：从 (0.66,0.44,−0.5) 沿 +Z 打射线，命中 `Machine_Feet@−0.0001` 后**直接跳到** `Machine_Body@0.26`，中间穿过 `Machine_Base` 的 bbox 却零命中。这比填充率更能证明底座是空的，也同时证明**脚上方没有底座实体**（脚与底座并非"悬空"，而是"顶上没东西"）。

## 四、四处与参考图的真实差距（分级）

| 部位 | 差距性质 | 与参考的偏离 | 修复工作量 | 风险 |
|---|---|---|---|---|
| **底座** | **结构级** | 空心桌板架（填充 12.8%）vs 实心碗形；方片脚 vs 圆截面短柱；`P1_BaseBand` 外凸环参考不存在；Bevel 被非均匀缩放压成 0.0085 | 重建 3 件 | **低**（不参与动画） |
| **螺丝孔** | **形态级（反了）** | 16 枚外凸黑螺帽 vs 每面 4 枚奶油色沉孔；无布尔沉孔；位置贴边 vs 参考实测位 | 16 个布尔沉孔 + 删 16 件 | 低（注意 `matrix_parent_inverse`） |
| **夹爪** | **形态级** | 椭圆管（1.42:1）+ 瘤节 + 无铰链 + 非等分 vs 扁叶（约 3:1）+ 圆销铰链 + 环绕；**配色基本没问题** | 改截面/去瘤节/补铰链/修角度 | **中**（必须复测 f31/f96/f147 抓取距离） |
| **出料口** | **结构级但被高估** | U 槽**存在**但法线朝内；机身盲孔（挖到 0.74 停）；唇橙关系反（橙高 0.236）；缺 L 形竖腿与圆勺；长托是 `MAT_Arm_Dark` 深灰块 | 翻法线 → 挖穿 → 修唇 → 补件 | **高**（牵动产品落座与出料动画） |

**总体判断**：四处都不是打磨级差距，都是结构/形态级。但出料口的真实状态比报告描述的好一档——**槽已经有了，是翻面和堵死**，不是从零重建。按"先翻法线看效果"的顺序做，出料口的工作量可能比报告估的低 30–40%。

## 五、建议修正的验收门槛

原报告 §3.3 的门槛大部分可用，但需改两处：

- ❌「橙腔：橙件 signed_volume > 0」——保留，但**改为第一优先**（翻法线即可达成），不是重建后才检查。
- ❌「爪色：新增 `MAT_Claw_Cream`，sRGB ≈ (0.90,0.81,0.69)」——**删除**。参考爪实测 (0.95,0.65,0.37)，应比当前琥珀更亮更暖，不是更浅更灰。
- ✅ 底座填充率 ≥ 0.85、脚嵌入 ≥ 0.02、唇顶 z > 橙口沿 z、三角面 ≤ 60k、抓取距离 0.006、循环闭合 0.000 —— 均合理，保留。
